# GridReserve Agent：氣象驅動負載預測與機組情境推演之台灣電網備轉風險 Domain AI Agent

> **物聯網數據分析與應用（DIC 3）期末專題重構計畫**  

## 專案簡介

**GridReserve Agent** 是一個以**台灣公開電力營運與氣象觀測資料**為基礎的電網備轉風險領域智慧代理人（Domain AI Agent）。針對近年半導體與 AI 用電成長帶來的供電壓力（台電預估 2026 年夏季尖峰負載達 4,294 萬瓩、夜尖峰達 3,853 萬瓩），以及大型機組突發事故（例如 2025 年 9 月興達新 2 號機與林口 2 號機事故共減少 210 萬瓩）所造成的備轉波動，本專案協助能源研究者、政策分析人員與關心供電情勢的公眾：

1. **預測未來尖峰負載（`FORECAST`）**：結合日曆與三站氣象特徵，輸出含 10% / 50% / 90% 分位數與 Conformal Prediction 校準區間的負載預測。
2. **推演機組停機情境（`WHATIF`）**：在指定機組停機或負載偏移情境下，以確定性規則計算備轉容量（$R_{\text{cap}} = S_{\text{adj}} - \hat{L}$）、備轉容量率（$r$）、五級供電燈號與「備轉 ÷ 最大單機容量（$N-1$）」指標。
3. **診斷歷史低備轉日（`DIAGNOSE`）**：找出備轉容量率低於 10%（黃燈以下）的歷史事件日，並與前 7 週同星期平均比較，歸因出力變化最大的機組群組。
4. **解釋領域規則與限制（`EXPLAIN`）**：結合領域知識庫與檢索增強生成（RAG），說明燈號邏輯、快慢速備轉品質差異、日夜尖峰差別及資料涵蓋邊界。

## 為什麼需要這個專案？（核心洞察）

根據對 2023-01-01 至 2026-08-31 共 **1,339 天**公開資料的初步探索（EDA）：

- **備轉容量率不可直接用天氣預測**：尖峰負載與三站平均最高氣溫相關係數約 **$0.75$**，但每日備轉容量率與氣溫相關係數僅約 **$-0.07$**；原因在於淨尖峰供電能力與負載高度連動（相關係數約 **$0.92$**），備轉本質上是調度後的結果。因此本系統採**預測與推演分離**：機器學習只預測天氣敏感的負載端，供電端與燈號交由確定性領域規則與情境運算。
- **備轉數字不等於真實風險**：融入五大領域思維（M1 備轉是保險、M2 快慢速品質比數量重要、M3 $N-1$ 單機事故思維、M4 日／夜尖峰區分、M5 機率不確定度），並明確標註資料限制與取捨。
- **零幻覺數字防線**：LLM 僅負責意圖理解、任務規劃與文字統整；所有數字必須經由工具輸出並通過**驗證關卡（Verification Gate）**檢查編號、單位與日期，超過資料範圍或驗證失敗時寧可**安全拒答／安全失敗**，絕不捏造數值。

## 系統架構（8 模組設計與流程）

本系統依據課程規範設計為 **8 模組架構**，搭配**三決策點、兩迴圈**處理流程與雙演算法（`Algorithm 1: GridReserve Agent`、`Algorithm 2: ClassifyLight`）：

```text
① 使用情境 ──▶ ② 查詢輸入 ──▶ ③ 規劃與推理 Agent (LLM Planner + 安全拒答)
                                     │
                 ┌───────────────────┼───────────────────┐
                 ▼                   ▼                   ▼
     ④ 資料取得與清洗         ⑤ 分析引擎           ⑥ 領域知識庫 (KB + RAG)
     (6 個 CSV、重算燈號率)    (分位數 ML / 歸因)    (雙邏輯燈號 / 175+ 機組 / N-1)
                 └───────────────────┼───────────────────┘
                                     ▼
                       ⑦ 情境推演與驗證關卡 (Verification Gate, 最多重試 2 次)
                                     │
                                     ▼
                       ⑧ 輸出與互動介面 (Streamlit 結論卡、區間圖、依據與限制)
```

### 供電燈號雙軌規則（`ClassifyLight`）
- **絕對值門檻（優先判斷）**：備轉容量 $\le 50$ 萬瓩為**黑燈**；$\le 90$ 萬瓩為**紅燈**。
- **百分比門檻**：備轉容量率 $\le 6\%$ 為**橘燈**；$< 10\%$ 為**黃燈**；$\ge 10\%$ 為**綠燈**。

## How to Run（規劃執行與實驗驗證流程）

實作完成後，專案將支援以下標準執行與驗證流程：

1. **資料下載與清洗**：將台電與中央氣象署 6 份原始 CSV 保存於 `data/raw/` 並記錄校驗碼，執行清洗管線產出合併後的 1,339 天乾淨資料集（含重算備轉容量率、微量降雨歸零、單位統一為萬瓩）。
2. **啟動互動式應用（模組 ⑧）**：
   ```bash
   streamlit run app.py
   ```
3. **執行 E1–E4 正式評估實驗**：
   - **E1 負載預測評估**：訓練期 `2023-01-01 ～ 2025-08-31`、滾動測試期 `2025-09-01 ～ 2026-08-31`，對比月平均、前一週同日與無氣象日曆模型，評估 MAE、MAPE、Pinball Loss 與 80% 區間涵蓋率。
   - **E2 事故情境回測**：以 2025 年 9 月興達／林口事故前狀態推演停機後備轉，對照 `09/09` 至 `09/23` 實際備轉變化量與燈號。
   - **E3 Agent 幻覺與溯源評估**：以 40 題程式生成問答集（預測 10、情境 10、歸因 8、解釋 6、超範圍陷阱題 6），比較「純 LLM」、「LLM + RAG」與「完整工具約束＋驗證關卡 Agent」之數字正確率（±1% 容許誤差）、溯源率、拒答正確率與幻覺率。
   - **E4 燈號規則邊界測試**：針對 `10%`、`6%`、`90` 萬瓩、`50` 萬瓩邊界值執行自動化單元測試（`pytest`）。

## Demo 展示情境範例

在 Streamlit 互動介面中，使用者可輸入以下四類查詢並檢視結論卡、區間圖表、工具依據與限制警語：

- **負載預測（`FORECAST`）**：*「預測明天尖峰負載大約多少？」* → 回傳氣象驅動預測中位數與 80% Conformal 區間，並說明不包含直接夜尖峰備轉資料之限制。
- **停機推演（`WHATIF`）**：*「若台中新 1 號機（130 萬瓩）跳機，備轉容量率與燈號會如何變化？」* → 扣除 130 萬瓩後重算 $R_{\text{cap}}$、$r$、$N-1$ 倍數與燈號變化。
- **事故歸因（`DIAGNOSE`）**：*「2025 年 9 月 23 日備轉為什麼偏低（6.08%）？」* → 標註黃燈事件並比對前 7 週同星期平均，列出出力下降機組群組（附註「出力不等於可用容量」警語）。
- **超範圍拒答（Safe Refusal）**：詢問無公開資料之民營電廠（IPP）或超出資料日期範圍的問題時，觸發安全拒答並說明原因。
